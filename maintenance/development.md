# 开发与维护

核心 Python 环境和四个框架环境分别锁定。根环境运行契约、领域文件实验和完整编码研究；框架示例使用自己的 pyproject.toml 与 uv.lock。

| 入口 | 用途 |
| --- | --- |
| npm run check | 文档、历史契约、新领域实验、完整研究和模拟模型接入 |
| npm run verify:core | 增加 Python 测试、类型、lint、检查器负例和站点验证 |
| npm run frameworks:check | 四个实际运行时与错误产物负例 |
| npm run verify | 核心验证和独立框架检查 |
| npm run pages:check | 站点构建、引用、许可、敏感信息和三视口检查 |

check 与 pages:check 会重建同一目录，应顺序执行。文档质量由逐页内容复核判断，不设置字数、关键词或固定标题门禁；tutorial:check 只验证教程清单里的输入、命令和验证契约引用。

产品事实按各自实际检查日期登记。定期任务检查时效和链接，不能自动刷新 Checked；TLS 或来源失败保持 pending。E0 来源事实与 E1 离线实验分开，真实框架使用假模型仍为 E1。

新增依赖先检查来源、锁定版本和分发元数据里的许可；更新后重跑对应示例。示例依赖由 uv 原样获取，仓库不复制第三方源码或二进制；保留各发行包的许可与通知。MPL 依赖若将来被修改或再分发，需另行满足对应源文件与通知义务。

失败时按契约、执行、验收、评测或站点分类，保留产物与第一条诊断。只恢复自己的候选代码和锁文件；已有结果不覆盖，外部动作不由本地 Git 回滚。

原始字节 hash 的新材料与公开产物通过 `.gitattributes` 关闭换行转换，保证 Windows 与 Linux 检出后内容身份不变。历史 JSON fixture 继续使用原有规范化 hash；运行源码 hash 记录实际执行时的文件字节，单独的 source_commit 不覆盖未提交改动。

## 本轮改动的回退边界

本地提交按核心执行与协议、四框架环境、站点与教程、作品集与复核记录分组。依赖这些功能的教程与入口应和实现一起回退；完整撤销时按提交逆序处理，不只删除某个文件。原始基线为 bd5ed23，历史公开实验保持原样。

源码和实验版本分别由提交与产物 hash 定位；本地提交没有推送或发布。回退前先检查当前工作树，保留自己的新增工作和运行失败记录。
