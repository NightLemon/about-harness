# 人在循环中的控制点

Human-in-the-loop 不是“随时问用户”，而是把不可逆、高风险或缺少业务判断的决策放到明确关口。

## 四类关口

1. **计划批准**：范围大、影响未知或需要多里程碑；
2. **危险动作批准**：删除、发布、付费、外发数据、权限提升；
3. **歧义升级**：多个选项会实质改变结果且无法从上下文推断；
4. **最终验收**：机器规则无法证明语义、视觉或业务正确。

## 一个好批准请求

包含动作、精确目标、理由、预计副作用、验证、回滚、费用/数据和不批准时的安全替代。批准只覆盖列出的动作，不能被后续任务隐含复用。

## 自动化边界

低风险、可逆、确定性的操作可由 policy 自动允许；高风险操作即使模型置信度高也需门禁。Hook/policy 执行硬约束，项目指令只塑造行为，不能作为安全隔离。

## 评测

报告人工介入次数、等待时间、被拒动作、误报/漏报和批准后失败。减少弹窗不是唯一目标；过度审批会让用户机械同意，同样降低安全。
