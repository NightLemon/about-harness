# Agent 循环

Agent 的价值来自“根据行动结果继续决策”，而不是一次生成很长的答案。

## 标准循环

```text
1. 接收目标与约束
2. 观察相关状态
3. 形成下一步动作
4. Harness 校验权限并执行动作
5. 把结果送回模型
6. 判断是否满足完成条件
7. 未完成则继续；异常则恢复、改路或停止
```

模型负责提出动作，harness 负责把动作变成现实并返回可信反馈。两者的边界越清晰，故障越容易定位。

## 每个阶段可能怎样失败

| 阶段 | 典型失败 | 优先修复 |
| --- | --- | --- |
| 目标 | “优化一下”没有范围 | 写出目标、边界与 `done when` |
| 观察 | 读错目录或读取过量 | 给入口、搜索顺序和排除项 |
| 决策 | 过早选定方案 | 对复杂任务先探索或要求比较方案 |
| 行动 | 工具参数错误、权限不足 | 改进 schema/示例，暴露权限原因 |
| 反馈 | 输出截断、错误被吞掉 | 返回结构化结果与退出状态 |
| 验证 | 模型自称完成 | 提供可执行测试或外部 evaluator |
| 恢复 | 无限重试同一路径 | 设重试预算与升级/停止条件 |

## 计划不是越多越好

计划适合多文件、方向不确定、风险高或验收复杂的任务。明确的一行修复先写长计划会增加上下文和延迟。可用一个简单门槛：如果无法用一句话描述预期 diff，先探索并计划；否则直接执行并验证。

## Harness 控制器的关键决策

### 何时继续

不要只依赖模型输出“完成”。优先检查确定性信号：测试退出码、生成物是否存在、schema 是否通过、视觉差异是否在阈值内。主观质量可增加第二模型或人工评审，但它不是确定性测试的替代。

### 何时重试

- 传输超时、限流：指数退避并保留请求幂等性。
- 工具参数无效：返回具体校验错误，允许模型修正一次。
- 方案本身失败：把证据送回模型，要求改变假设；不要原样重试。
- 权限拒绝：说明边界，寻找权限内路径；不能静默放宽权限。

### 何时停止

达到完成条件、预算耗尽、重复失败、需要新授权或外部状态不会改变时，应显式停止。停止信息至少包含：当前状态、证据、尚未完成项、需要谁做什么。

## 人在循环中的位置

人工审批应该守住有真实后果的边界，例如生产变更、公开发布、付费、删除与权限变化。对每个无害读操作都弹窗会导致审批疲劳；更好的做法是 sandbox 内自动、越界时审批，并把动作目标和影响说清楚。

## 一次高质量任务轨迹

```text
用户：修复登录超时后的刷新失败；先复现，不能改变 token 有效期。
Agent：定位认证入口与现有测试。
工具：搜索 refresh 逻辑 → 返回 4 个候选文件。
Agent：读取最相关实现和测试，提出竞态假设。
工具：新增失败测试并运行 → 稳定失败。
Agent：做最小修改。
工具：运行目标测试与认证测试集 → 全部通过。
Agent：复查 diff，报告根因、修改和测试证据。
```

它的关键不是长推理，而是每个假设都能被工具反馈约束。
