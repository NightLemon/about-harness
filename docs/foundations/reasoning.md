# 推理预算、规划与回退

推理预算是 harness 分配给模型的时间、token、调用次数或产品档位，不等于模型能力本身，也不能补偿缺失上下文、坏工具或不可观察的验收。

## 先判断任务结构

- 确定性、局部、低风险：直接执行并快速验证；
- 多文件、多约束：先形成可检查计划与里程碑；
- 信息不足：先检索或提问，不增加盲目推理；
- 高风险副作用：推理后仍需确定性 policy 与人工批准。

## 预算控制

同时限制 model calls、steps、timeout、cost 和并发。任何一个耗尽都产生明确 stop reason 与 checkpoint。不要无限重试到“看起来成功”；重试只用于被分类为暂时性的错误。

## 反思的适用边界

反思可以发现遗漏，但也会确认偏误、消耗预算或重写正确结果。只有当外部 validator 提供新信号时再反思；同一上下文上重复“再想一遍”不自动增加证据。

## 路由与降级

路由输入包括任务类型、风险、上下文、工具需求、延迟和成本。失败时可缩小任务、切换 adapter、减少工具或升级模型；每次改变一个主要变量并保存原基线。详见[推理与路由优化](/optimization/reasoning-routing)。

## 工作例：一次多文件修复

基线给 20 分钟、12 个步骤和固定测试命令。模型先定位失败，再形成三步计划；每完成一步都用外部测试产生新信号。若第 8 步仍没有更接近验收，controller 保存 checkpoint 并停止，而不是让模型无限“再想一遍”。候选只提高 reasoning 档位，其他输入保持相同，才能估计预算的真实作用。

## 失败诊断

没有行动就耗尽预算，检查任务契约与可用工具；反复编辑同一文件，检查 validator 信号和状态；高预算反而变差，检查上下文污染与过度反思；timeout 后副作用不明，先核对幂等记录。预算耗尽是可解释停止原因，不是自动切换高权限的理由。
