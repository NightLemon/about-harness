# 记忆的生命周期

记忆不是“把更多历史塞进上下文”。它是带来源、写入规则、检索条件、失效与删除能力的数据系统。

## 四类状态

| 类型 | 生命周期 | 例子 | 主要风险 |
| --- | --- | --- | --- |
| 当前上下文 | 单次模型调用 | 当前 diff、工具结果 | 超预算、污染 |
| 工作记忆 | 单次 run | 计划、已完成步骤 | 恢复不一致 |
| 会话记忆 | 多轮会话 | 分支、摘要、偏好 | 有损压缩 |
| 长期记忆 | 跨会话 | 已验证项目约定 | 过时、错误写入、隐私 |

## 写入前问五个问题

谁提供？是否可信？什么任务需要？何时失效？用户如何查看和删除？模型的猜测、网页指令和失败轨迹默认不能自动升级为长期事实。

## 检索不是全量注入

先按作用域、权限、来源和时效过滤，再按任务相关性排序；结果需携带 source、created/checked、expires、trusted 和 evidence level。检索不到时返回“没有足够证据”，不要用相似文本填空。

## 失效、压缩与删除

TTL 只解决时间过期，版本化规则还需在依赖/分支/产品版本变化时失效。压缩保留决策、证据、未决项和恢复点，丢弃可重建噪声。删除同时覆盖索引、向量、副本、trace 与公开结果。

## 评测

测试正确检索、错误检索、过期、污染、删除和恢复。M3 的 `LongTermMemory.search(..., trusted_only=True)` 是 E1 教学实现，不代表生产级向量数据库。
