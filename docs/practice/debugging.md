# 问题诊断

先定位失败发生在哪一层，再决定换模型还是改 harness。

## 快速诊断树

```text
任务失败
├─ Agent 是否看到正确目标/文件/错误？
│  ├─ 否 → 工作目录、指令加载、检索、截断、压缩
│  └─ 是
├─ 所需动作是否有工具且权限允许？
│  ├─ 否 → 工具/认证/sandbox/审批；不要先换模型
│  └─ 是
├─ 工具调用是否有效并返回可恢复错误？
│  ├─ 否 → schema、描述、adapter、错误格式
│  └─ 是
├─ 是否有可运行的完成检查？
│  ├─ 否 → 补测试/构建/截图/rubric
│  └─ 是
└─ 证据齐全仍反复判断错误？
   ├─ 是 → 拆小、提高推理、换更合适模型
   └─ 否 → 修任务契约或循环停止条件
```

## 症状对照

| 症状 | 高概率原因 | 先做的检查 |
| --- | --- | --- |
| 修改错误目录 | cwd/项目根识别错误 | 输出 cwd、Git root、已加载指令 |
| 一直重读同文件 | 未维护状态、工具结果不定位 | 检查轨迹，返回路径/行号与已读摘要 |
| 声称测试通过但未运行 | 完成条件不可执行 | 明确命令；用 hook/CI 阻止无证据完成 |
| 调高推理仍参数错误 | provider/工具 schema 不兼容 | 最小 tool-call smoke test |
| 长会话突然违背约束 | 压缩丢失或上下文拥挤 | 检查摘要；保存状态后新会话 |
| 权限提示太多 | allowlist 太碎或无 sandbox | 分离安全读操作与高风险写动作 |
| 从网页读到指令后外传数据 | prompt injection 与权限过宽 | 撤销凭据、审计调用、收紧工具/授权 |
| 快模型成本反而高 | 重试、纠正和冗余读取 | 看总任务成本，不只看单 token 价 |

## 最小复现包

提交 bug 或比较配置时包含：harness/模型/provider 版本、surface、精简任务、最小仓库或 fixture、配置（去密）、工具列表、期望/实际、完整错误、是否可重复。不要上传 session 前先假设其中没有密钥。

## 何时新开会话

任务已改变、上下文混入多个失败方案、相同纠正出现两次、或压缩摘要丢失关键边界时，先把确认事实与当前 diff 写入文件，再开干净会话。若问题是权限/工具不可用，新会话不会修复环境。

## 何时换模型

在已确认目标、上下文、工具、权限和验证都正确后，模型仍在相同推理任务上反复失败；或任务需要当前模型不支持的模态、上下文、语言/领域能力时。换模型后仍要固定其他变量做 A/B，避免把偶然成功当成根因。
