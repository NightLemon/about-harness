# 模型与服务：模型权重之外，还要固定什么

模型回答能力只是运行链的一部分。Provider（服务供应方）接收请求、解释参数、计量用量；推理运行时加载权重、管理显存和调度请求；Harness（工作环境）决定读什么、调用什么以及何时结束。三层中的任何一层变化，都可能改变你观察到的结果。

本页解释服务选择，精确模型的资格测试见[模型适配](/models/adaptation)。产品定位按 **2026-09-21** 实读的官方资料核对，均为 E0；没有运行服务器、下载权重或调用在线模型。

## 两条部署路径

| 路径 | 项目得到什么 | 项目仍需承担什么 |
| --- | --- | --- |
| 托管模型 API | 提供方维护推理基础设施，通过请求/响应使用模型 | 数据流、身份、预算、协议适配、重试和验收；记录区域与精确身份 |
| 自托管权重 | 控制权重、运行时、硬件和部署配置 | 权重许可、容量、补丁、隔离、监控、调度和服务成本；不自动得到更好隐私或质量 |

有些工具同时连接云模型和本机模型，产品名称不能替代运行位置。Ollama 的当前文档同时列出本地运行和云模型路径。[FACT:ollama-overview] 必须记录请求实际发往哪里，不能把“装在本机”推导成“数据从不出机”。

## 三类推理服务入口

| 对象 | 本次来源支持的定位 | 适合先研究什么 | 不能从名称推出什么 |
| --- | --- | --- | --- |
| vLLM | 模型推理与服务库，文档包含批处理、缓存和协议服务入口 [FACT:vllm-serving] | 并发请求、硬件利用、模型解析器与服务吞吐 | 任意模型/量化/工具调用组合兼容，或本任务一定更快 |
| SGLang | 大语言及多模态模型服务框架 [FACT:sglang-serving] | 服务调度、模型支持范围与实际部署约束 | 支持目录中的所有模式都在你的硬件上通过 |
| Ollama | 在应用或编码助手中使用本地/云模型的入口 [FACT:ollama-overview] | 开发接入、模型来源和运行位置 | 本机安装即离线，兼容客户端即完整协议等价 |

这些对象不是 Agent 框架，也不会替你定义任务完成条件。选择时先固定一个模型和一个负载，测端到端任务延迟、失败率和总体成本；吞吐宣传或单次生成速度不能代替工作流测量。

## 模型家族怎么读

现有专题分别解释 [OpenAI](/models/openai)、[Anthropic](/models/anthropic)、[Google Gemini](/models/google)、[Qwen](/models/qwen)、[DeepSeek](/models/deepseek)、[Llama](/models/llama)。先核对精确 ID、模型卡、服务接口和支持参数，再设计比较。

“别名可能变化”是需要检查的问题，不是所有供应方的统一事实。例如当前 Anthropic 目录将 Claude API 的模型 ID 描述为固定快照；不能因为 ID 不含日期就擅自当作滚动别名。[FACT:anthropic-catalog] 开放权重则还需记录仓库 revision、权重和 tokenizer 身份、聊天模板、量化方式、工具与推理解析器。只记录家族名不足以复现。

## 缓存、推理预算与请求调度

Prompt caching（提示缓存）复用相同输入前缀的计算；它不同于把上次答案直接返回的结果缓存。OpenAI 当前文档说明共享前缀与缓存命中有关，保留同一会话并不保证命中。[FACT:openai-prompt-cache]

工程上要同时观察：实际输入量、缓存读取量、未缓存量、首 token 延迟、总任务耗时、重试与验收结果。为了提高命中率塞入无关上下文，可能增加总成本和错误。缓存也不保证旧证据仍有效，权限或数据版本变更时须重新确认可用范围。

推理预算影响模型单次计算，宿主的步数、工具次数、总时限和费用上限是其他控制层。更高推理预算不自动增加宿主 deadline（截止时间）；并发变多也可能放大排队和限流。比较时固定工作负载并明确哪一个变量改变。

## 多模态服务还需检查什么

同一模型名称不表示所有 surface（使用界面）支持相同输入。图像分辨率、音频编码、视频时间采样、流式事件、工具调用和结构化输出要分别做资格探针。缺失 modality（模态）支持时明确拒绝，不静默删除图片或把音频事件当作普通文本。

实时交互还需记录中断、取消、迟到结果和工具副作用，继续见[多模态与交互](/ecosystem/multimodal)。协议实现细节见[协议兼容性](/models/protocol-compatibility)，同一冻结响应的回放与两次独立生成使用不同断言。

## 选择前的一张记录

记录任务和验收、精确模型、供应方和区域、运行时与硬件、模板和解析器、输入类型、并发、预算、费用单位、数据保留政策以及回退对象。先检查未知项会不会改变决定；尚无实测时把性能与可用性写为 `untested`。

可以先运行[固定候选练习](/practice/ecosystem-workshop)，观察“有正确候选”和“选对候选”的差别。该 E1 练习不运行上述服务，不能作为购买、部署或模型排名依据。
