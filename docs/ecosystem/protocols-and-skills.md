# 协议与技能：连接工具、委派任务和复用流程

三个相似的问题需要不同机制：让 Agent 访问工具；让两个独立 Agent 交换任务；让 Agent 按需读一套操作说明。先确认你要解决哪一个，再选择协议或扩展形式。

以下产品与规范材料实际核对于 **2026-09-21**，来源事实为 E0。协议版本不等于客户端支持版本；当前项目没有启动真实 MCP/A2A 服务或安装 Skills。

## 三种边界

| 机制 | 主要交换什么 | 项目仍需负责什么 |
| --- | --- | --- |
| MCP：Model Context Protocol（模型上下文协议） | 宿主、客户端、服务端之间的工具、资源等能力 [FACT:mcp-spec] | 身份、可用能力、权限、数据流和执行结果 |
| A2A：Agent2Agent（智能体间协议） | 独立 Agent 之间的发现、委派和结果交换 [FACT:a2a-protocol] | 委派范围、预算、取消、结果验收和信任关系 |
| Agent Skills（智能体技能格式） | 可发现的说明和支持文件，以 `SKILL.md` 为入口 [FACT:agent-skills-format] | 何时加载、来源版本、脚本权限和卸载 |

MCP 可以接到另一个 Agent 的工具，但不会因此自动获得 A2A 的任务语义；一份 Skill 可以说明如何使用工具，却不是远程调用协议，也不会自动授予工具权限。

## MCP 的当前规范与可选扩展

本次读取的 MCP 规范版本为 **2026-07-28**，概览包含无状态请求及逐请求能力协商。旧版材料的生命周期和传输假设不能无条件用于该版本；迁移时固定双方实际支持的版本并逐字段核对。[FACT:mcp-current-protocol]

本次来源也列出可选扩展：

- **Tasks**：长操作可以返回持久任务句柄，客户端轮询进度、处理中途输入并获取结果。[FACT:mcp-tasks] 任务句柄解决关联和恢复访问，不替外部业务实现幂等或对账。
- **Apps**：工具关联可交互的 HTML 界面，由支持的宿主嵌入显示。[FACT:mcp-apps] 界面展示、工具请求、宿主授权和执行回执是不同事件；按钮出现不表示操作已批准或完成。

不能仅看到“支持 MCP”就假设支持全部扩展。应分别记录协议版本、扩展名、客户端/服务端能力、认证方式和失败语义。声明缺失或双方不匹配时，停止对应功能或退回已验证路径。

## A2A 委派不是放弃控制

A2A 官方介绍的核心场景是不同系统的 Agent 交换信息、委派子任务和协调工作。[FACT:a2a-protocol] 对本地调用者而言，下游输出仍是需要验证的观察，而不是新的高优先级指令。

例如研究 Agent 委派“从两份指定文档提取条款”，应连同范围、输入身份、期限和输出要求发送；下游要求新增联网、读取其他租户数据或发邮件时，需要调用者重新判断授权。把一整段用户对话无筛选转交给第三方，既增加成本，也可能扩大数据暴露。

超时只说明调用者没有及时得到结果；取消已接收、任务真正停止、外部动作已经提交是不同状态。结果有未知副作用时进入对账流程，不能换任务 ID 盲重发。

## Skill 从发现到执行

开放格式以目录中的 `SKILL.md` 提供元数据和说明，并允许附带脚本、参考资料和资源；渐进披露使调用者可以先看到名称/描述，再按需读正文和支持文件。[FACT:agent-skills-format]

推荐把可复用流程与长期项目约束分开：稳定的“哪些操作不允许”属于宿主策略或项目规范；仅在审核文档时需要的步骤可以放入 Skill。脚本是可执行代码，需要核对来源、输入、输出、副作用和依赖，不能因为包装在 Skill 中就跳过权限检查。

同一开放格式在产品中的发现、版本和执行规则仍可能不同。OpenAI 当前文档区分 Responses 的技能包附加方式与 Agents API 沙箱目录发现方式。[FACT:openai-skills-lifecycle] 不应把一个 surface 的上传/版本字段复制成另一个 surface 的配置。

## 程序化工具调用解决什么问题

Programmatic Tool Calling（程序化工具调用）让模型生成程序来组织一组工具调用，在程序内筛选或聚合中间结果。OpenAI 当前文档描述了受限的 JavaScript 运行环境，并按 API 区分工具可被直接调用或由程序调用的配置。[FACT:openai-programmatic-tools]

适合的例子是查询三份固定库存再汇总；不适合一次包住的例子是每步都需要新的语义判断、用户审批或完整原生引用的研究任务。程序必须保留错误、身份、必要来源和共享预算，不能因为最终返回更短就隐藏某一次调用失败。

少返回一些中间数据可能降低上下文负担，但并不自动减少工具次数，也不能直接推导模型质量、token 或费用收益。[生态工作坊](/practice/ecosystem-workshop)用本地假工具展示这种区别，明确不运行该真实 API。

## 如何验证一个组合

先记录协议与扩展版本、双方能力、认证主体、允许资源和动作、任务/调用 ID、超时取消与未知结果处理。再设计四个负例：能力只在一端声明；Skill 建议越权；工具结果冒充指令；任务取消后返回迟到成功。

离线练习只能检查内部规则。真实互操作需要另行授权后对精确客户端/服务端版本运行探针；产品文档和 JSON 能解析都不能替代该证据。继续阅读[工具设计](/foundations/tools)、[多 Agent 编排](/foundations/multi-agent)与[状态恢复](/foundations/state-reliability)。
