# 多模态 Agent：观察不是看见，完成不是屏幕变化

多模态 agent 同时处理文本、DOM、截图、图像、音频、实时事件和工具结果。难点不在于输入格式更多，而在于不同观察的身份、延迟、可操作性和可信度不同：同一个按钮在 DOM 中有稳定 selector，在截图中只是像素区域，在音频中可能只是用户口述的目标。Harness 必须保存它看到了什么、何时看到、依据什么执行，以及外部动作是否已经发生。

本页讨论稳定的设计机制。Browser Use 的 Cloud 产品事实单列为 E0；本仓库没有启动云浏览器、本地浏览器、视觉模型、音频流或实时双向会话，因此不把页面、fixture 或离线检查当作这些能力的可用性证据。

## 先区分观察与执行

Observation（观察）是进入下一步决策的证据，不因来自摄像头、浏览器或工具就自动可信。Action（动作）才会请求点击、输入、上传、发送或调用外部系统。多模态系统应把二者用稳定 ID 连接：

```text
observation_id / modality / captured_at / source / hash
  → interpretation or extracted fields
  → proposed action / policy decision / approval reference
  → receipt or unknown outcome
```

截图、OCR 结果、音频转写和 DOM 文本都可能误识别、过期或被注入。它们可以帮助模型提出动作，却不能自行扩大路径、域、账号、文件上传或付款权限。最终执行仍由 schema、policy、approval 和目标系统能力决定。

## DOM、截图与 Computer Use 的取舍

DOM（文档对象模型）观察提供页面结构、属性、可访问名称和可定位元素。它适合验证“是否存在这个表单字段”“当前 URL 是否在 allowlist”以及用结构化 selector 执行可审计动作。它的局限是：canvas、远程桌面、原生窗口、绘图内容和视觉布局未必能完整表达在 DOM 中。

Screenshot（截图）观察提供渲染后的像素，包括 canvas、图表、弹窗、布局错位和非 DOM 表面。Computer Use（计算机使用）通常依赖这类视觉状态进行鼠标、键盘或触屏式操作。它能覆盖 DOM 不可见的界面，却很难天然证明“第 428 像素处仍是同一对象”；缩放、滚动、动画、遮罩、主题和延迟加载都可能让坐标失效。

工程上不要把二者混成一个“页面已看见”。优先用 DOM 或无障碍树确认稳定身份和业务状态；只有视觉信息不可替代时才使用截图，并记录 viewport、缩放、窗口/页面 ID、截图 hash、坐标系、元素附近证据和截图时间。视觉操作后再以 DOM、页面结果或业务 receipt 验证，而不是仅凭点击动作返回。

失败案例是截图里出现“提交”按钮，模型点击后页面动画尚未完成，随后又根据旧截图重复点击。第二次请求可能已发送，UI 却还没有刷新。正确控制是为动作绑定 observation ID 和 deadline，等待可验证的新状态；超时后把结果标为 unknown，先查询页面或目标系统，而不是继续沿用同一截图重放。

## Browser Use Cloud 与本地路径：E0 产品事实

截至 2026-09-21，Browser Use 官方 Cloud quickstart 将 Cloud Agent 和 Browser Infrastructure 分成两条 Cloud API V4 路径：前者由服务驱动浏览器，后者让 Playwright/Puppeteer 通过 CDP 连接托管浏览器；同一官方页面又把本地 agent 指向 open-source library，并明确二者 API 不同。[FACT:browser-use-cloud]

因此 Cloud run/session/workspace/profile 身份、托管浏览器生命周期和本地库对象不能假定可互换。浏览器抽象改变时，要重新确认认证、状态存储、取消、文件、录制、网络与费用边界。这里没有安装或调用 Browser Use，以上只是官方 quickstart 的 E0 产品事实，不证明任何本地或云路径已兼容、可用或安全。

## 图像与文档：提取结果要保留证据边界

图像、PDF 页面、扫描件和图表的常见路径是原始文件 → 解码/渲染 → OCR、布局或视觉提取 → 结构化字段/引用 → 任务决策。每一步都要保留来源文件 hash、页码/帧号、解析器版本、区域或引用定位和置信/未知状态。

不要把 OCR 文本当作原始文档。表格列错位、单位丢失、脚注遗漏和图例颜色误读，会让“文字看起来合理”的结果变成错误数据。高影响字段使用交叉验证：原始局部图像、结构化规则和业务范围检查至少有两个独立信号；无法确认时返回需要人工核对，而不是将低置信值塞入后续工具参数。

例如，发票图像把 `1,000` 读成 `1,800`，模型再以此创建付款草稿。即使支付工具需要审批，审批页面也可能只展示模型摘要。正确做法是把原图区域、提取值、币种/单位和异常范围一起带入 preview，并在金额或收款方不确定时阻断自动提交。

## 音频、实时双向与中断

音频输入至少区分原始流、转写、说话人/时间段和最终解释。转写是派生证据，可能漏掉否定词、数字或说话人切换；不要因为它到达得快就覆盖用户已确认的文字 Task。对每段保存 session、序号、时间戳、语言/转写器身份和是否最终稳定的状态。

实时双向系统还要定义 interruption（中断）：用户打断模型朗读、网络断开、工具在说话期间完成、取消先到而外部 receipt 后到，都是不同状态。取消语音输出不等于取消模型调用；取消模型调用也不等于撤回已发出的外部请求。controller 应传播 cancellation token，并在迟到结果到达时记录真实副作用、拒绝将其伪装成未发生。

失败案例是用户说“先不要发送”，本地音频转写延迟，而发送动作已按较早的转写启动。随后 UI 显示 cancelled，但远端邮件服务返回成功 receipt。系统必须保留两条事实：用户取消已观察，外部发送可能或已经完成；后续进入对账、通知或补偿流程，而不是删除记录。

## 多模态验收需要两个层次

第一层验收观察质量：输入是否属于正确 session/page/frame，解析是否完整，引用是否可回到原始对象，敏感内容是否脱敏，过期观察是否被拒绝。第二层验收业务结果：目标页面、文件、记录或外部系统是否满足 Task acceptance，禁止动作是否为零，未知副作用是否已对账。

仅测“模型描述截图正确”无法证明点击、上传或写入正确；仅测“按钮被点击”也无法证明用户目标完成。把以下内容分开报告：

| 层次 | 示例断言 | 不能证明 |
| --- | --- | --- |
| 观察 | screenshot hash 与 page/frame ID 匹配，OCR 引用可定位 | 业务对象已修改 |
| 动作 | policy 在规范化目标上允许，参数通过 schema | 服务端已提交 |
| 副作用 | receipt 或目标系统查询已对账 | 用户真正满意或任务覆盖充分 |
| 业务验收 | 结果满足冻结 acceptance 且禁止动作未发生 | 其他未测任务也安全 |

多模态 E1 fixture 可以验证 observation schema、过期截图拒绝、脱敏和 policy 顺序；它不能证明真实视觉理解、实时中断、浏览器兼容或云端副作用。接入任何真实表面前，先用隔离 profile、合成文件、测试账号/目标、窄 allowlist 和明确停止条件，再取得所需授权。

不要把图像、转写和 DOM 片段直接拼成一段无来源 prompt。不同模态的冲突应保留为冲突：例如 DOM 标题显示“草稿”，截图却显示旧的“已发送”提示时，先刷新并记录两个 observation，而不是让模型任选一个。跨模态一致性是需要验证的结论，不是输入到达同一上下文后自然成立的事实。

## 工程取舍与离线练习

| 选择 | 适用情况 | 主要风险 | 先做的验证 |
| --- | --- | --- | --- |
| DOM/结构化工具 | 元素和状态可稳定查询 | 忽略视觉层问题 | selector、URL、业务状态三者一致 |
| Screenshot/Computer Use | 非 DOM、canvas 或原生 UI | 坐标漂移和旧画面重复执行 | observation identity 与动作后新状态 |
| OCR/视觉提取 | 扫描文档、图表、票据 | 数值/单位/布局误读 | 原始区域、范围规则与人工阈值 |
| 实时音频 | 需要低延迟交互 | 转写滞后和取消竞态 | segment 版本、cancel 与 receipt 对账 |

做一个本页的 E0 纸上练习：输入三条合成记录——截图 o1 在 t=1 显示“未发送”，DOM o2 在 t=2 显示“发送中”，receipt r1 在 t=4 确认操作 k1 已完成；用户在 t=3 取消。画出 observation-to-action trace，标注 ID、过期条件、取消与对账。合格产物不根据旧截图重发 k1，并将“取消后收到已完成回执”交给对账；直接宣称取消意味着未发送为失败。只需临时文本，无设备、网络或真实数据；删除自己的草稿即可清理，修订失败回到冻结三条记录。此练习不证明 UI 自动化已实现；可执行的内部 E1 机制另见[生态工作坊](/practice/ecosystem-workshop)。
