# Judge 与人工评分

Judge（模型裁判）是用另一个模型评价开放式输出的方法，只适用于确定性规则无法覆盖的维度。

## 何时使用

编译、测试、schema、hash、安全策略等能确定判断的内容不要交给模型 judge。只在可读性、解释质量或开放式研究覆盖等无法完全规则化的维度使用 judge，并保留人工抽样。

## 控制偏差

盲化配置名、随机或轮换候选顺序、固定 rubric 与 prompt hash、保存 judge 模型/provider/version、让 judge 引用具体证据。用人工标注集检查一致性；位置偏差、自偏好和冗长偏好必须单独测。

## 失败与升级

Judge 输出 schema 无效、引用不存在、候选身份泄漏或与人工基准分歧超阈值时，结果进入人工复核，不自动采用。Judge 也是模型调用；本仓库只提供离线协议，不运行 judge。

下一步：[回归](/evaluation/regression)。

## 工作例：最小评分协议

给 judge 两个匿名候选、固定 rubric 和原始任务断言。输出必须列每个维度分数、引用候选中的具体片段、无法判断项和总分；候选顺序随机化，再交换顺序重复一次。用人工标注的小集合校准一致性，不能因为 judge 输出 JSON 合法就相信评分。

## 失败诊断

顺序交换后赢家改变，检查位置偏差；长答案总得高分，检查冗长偏好；judge 引用不存在，结果直接无效；judge 与人工分歧集中在一类任务，分层报告而不是平均掉。Judge 模型、provider、版本、prompt 与 rubric hash 任一变化都建立新配置。
