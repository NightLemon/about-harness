# Coding Agent 模式

## 工作流

理解任务 → 定位代码/指令 → 建立 baseline → 小步修改 → 测试/静态检查 → 审阅 diff → 总结与恢复点。模型不能用“代码看起来合理”替代构建与测试。

## Harness 重点

目录级指令、快速搜索、结构化 patch、shell timeout、worktree 隔离、最小写权限、测试发现、Git diff 与 checkpoint。并行 agent 不写同一 checkout。

## 典型失败

改错仓库/分支、覆盖用户改动、只修测试不修行为、生成物进 Git、无限试错、危险 shell、依赖升级扩大范围、没有复现失败。

## 指标

任务级测试/验收、patch 正确性、回归、安全违规、工具错误、人工介入、时间与成本。代码行数和“通过一次”不是充分指标。

离线案例使用固定小仓库做测试驱动修复，并包含越界 patch 与恢复负例。

## 最小工作例

任务是“修复分页函数漏掉最后一项”，而不是“优化整个模块”。Harness 先保存输入 commit 和失败测试，再只开放目标目录写权限；模型提交 patch 后运行 empty、single、multiple 三个断言。测试通过后仍检查 diff，确认没有新增依赖、没有生成物，也没有把断言改成迎合错误实现。这个例子把模型生成与业务验收分成两个责任层。

## 诊断顺序

失败时先问任务是否可复现，再看指令加载、检索范围、patch 应用、shell 退出码和测试选择；最后才判断模型能力。若同一错误反复出现，缩小上下文并提供失败断言，而不是立即提高权限或换更贵模型。超时保留 checkpoint，未知生成物先隔离。
