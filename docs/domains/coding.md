# Coding Agent 模式

## 工作流

理解任务 → 定位代码/指令 → 建立 baseline → 小步修改 → 测试/静态检查 → 审阅 diff → 总结与恢复点。模型不能用“代码看起来合理”替代构建与测试。

## Harness 重点

目录级指令、快速搜索、结构化 patch、shell timeout、worktree 隔离、最小写权限、测试发现、Git diff 与 checkpoint。并行 agent 不写同一 checkout。

## 典型失败

改错仓库/分支、覆盖用户改动、只修测试不修行为、生成物进 Git、无限试错、危险 shell、依赖升级扩大范围、没有复现失败。

## 指标

任务级测试/验收、patch 正确性、回归、安全违规、工具错误、人工介入、时间与成本。代码行数和“通过一次”不是充分指标。

M5 案例使用固定小仓库做多文件测试驱动修复，并包含坏 patch 与恢复负例。
