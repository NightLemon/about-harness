# 知识地图

Harness 把概率模型包在一个可执行、可约束、可观察的系统里。可以把它分为七层：

| 层 | 核心问题 | 常见机制 |
| --- | --- | --- |
| 目标层 | 什么算完成？ | [任务契约](/optimization/prompting)、验收条件、计划 |
| 上下文层 | 模型此刻能看到什么？ | [指令](/foundations/instructions)、[检索、记忆、压缩](/foundations/context) |
| 推理层 | 选哪个模型与预算？ | [模型路由、推理强度、重试](/optimization/model-fit) |
| 行动层 | 模型可以做什么？ | [文件工具、shell、浏览器、MCP、CLI](/foundations/tools) |
| 控制层 | 哪些动作允许发生？ | [sandbox、allowlist、审批、策略](/foundations/security) |
| 反馈层 | 如何知道做对了？ | [测试、构建、截图、评审、evaluator](/foundations/agent-loop) |
| 运行层 | 如何持续、复现与审计？ | [session、日志、成本、版本锁定](/optimization/experiment) |

## 两个相互作用的循环

单次任务运行在内循环：

```text
目标 → 观察 → 决策 → 工具调用 → 读取结果 → 验证 → 完成或继续
```

Harness 优化运行在外循环：

```text
收集失败 → 分类原因 → 修改一个变量 → 重跑任务集 → 比较指标 → 固化改进
```

只做内循环，你会重复手工纠正；只做外循环而没有稳定任务集，你会对噪声过拟合。

第一次使用这张图时，给七层各写一句“我当前用什么实现”。空白层不一定是缺陷，但若“目标、控制、反馈”为空，先补它们再扩大自动化。


## 稳定知识与易变事实

跨产品稳定的知识包括：上下文是有限资源、工具结果也是上下文、验证必须可观测、权限应遵循最小化、压缩会丢失信息。易变事实包括模型名称、默认推理档位、配置路径、命令参数和产品可用性。

本文档对易变事实在[资料来源](/references/sources)中记录核对日期。实际操作前仍应查看目标版本的官方文档与 `--help`。
