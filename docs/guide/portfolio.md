# 学习作品集与评分规则

阅读完成不等于能力形成。作品集要求读者提交六项可检查产物。

## 六项产物

1. **完整知识地图**：标出目标工作环境的 loop、上下文、指令、记忆、工具、权限、验证、恢复和治理。
2. **最小 harness 实现**：能使用 fake/replay 完成、停止、拒权、超时和恢复，并产生结构化 trace。
3. **指定模型适配卡**：记录精确模型身份、provider、adapter、harness、surface、协议、能力假设、预算和结论边界。
4. **配对实验报告**：保存任务集、fixture hash、基线、候选、重复、指标、失败类型和晋级判断。
5. **安全边界与威胁模型**：说明不可信输入、资产、权限、审批、检测、停止和事件恢复。
6. **跨 harness 迁移报告**：把同一任务在 Codex、Pi、Claude Code 中的指令、工具、权限、状态和恢复职责逐项映射。

## 必过门禁

以下任一失败，总分不再计算：

- 安全边界明确，没有未解释的危险权限或秘密处理缺口；
- 环境、版本、fixture、配置和命令可复现；
- 验证证据、失败记录和结论边界齐全，不把 E1 写成 E2/E3。

## 评分

| 维度 | 权重 | 评分问题 |
| --- | ---: | --- |
| 正确性 | 40% | 术语、实现、指标和结论是否与证据一致？ |
| 因果解释与证据 | 25% | 能否区分模型、adapter、harness、fixture 与基础设施根因？ |
| 迁移性 | 20% | 结论能否映射到另一 surface/harness，并清楚说明不能迁移之处？ |
| 效率与成本 | 15% | 是否报告时间、token/费用、人工介入和失败成本？ |

总分至少 80%，且每个维度至少得到该维度满分的 60%。例如“正确性”至少 24/40。

## 提交证据清单

每项产物附：版本、日期、环境、输入 hash、执行命令、退出码、机器可读 artifact、失败样例、恢复方式和 evidence level。没有运行的步骤必须写“未运行”和原因，不能粘贴预期输出冒充结果。

## 自评流程

先跑必过门禁，再由两次独立检查评分；分差超过 10 分时逐项对齐 rubric。模型 judge 只能作为辅助，最终报告保留规则/测试证据和人工确认项。
