## 六项交付物

| 产物 | 必须回答 |
| --- | --- |
| 知识地图 | 谁提出动作、授权、执行、保存状态和验收？ |
| 最小 Harness | 正常、拒权、坏输入、超时与恢复怎样结束？ |
| 模型适配卡 | 精确组合通过了什么资格，什么仍未验证？ |
| 配对报告 | 输入是否一致，差异、失败与不确定性是什么？ |
| 安全评审 | 资产和威胁如何连接到实际控制与负例？ |
| 迁移记录 | 哪些职责可迁移，哪些缺口需要补偿？ |

每项引用同一个任务，不另造六套背景。模板格式可以变化，证据链不能丢失。

## 先过资格门槛

安全边界、可复现性、证据诚实、独立验收、恢复能力和公开数据卫生必须全部合格。缺任一项先修复，不用其他维度的高分抵消。

完成声明要引用真实结果；未知用量、未运行产品和无法恢复的外部状态分别标明。至少保留一个真正能使旧实现失败的负例。

## 再评分

| 维度 | 权重 | 判断依据 |
| --- | ---: | --- |
| 正确性 | 40% | 概念、实现、断言与结论一致 |
| 因果解释与证据 | 25% | 能定位第一处分歧，排除替代解释 |
| 迁移性 | 20% | 映射职责、说明缺口和补偿 |
| 效率与成本 | 15% | 覆盖失败、工具、人工和维护成本 |

四项各按 0–100 分评分。通过要求为加权总分至少 80，每项原始分至少 60。60 分表示关键证据基本可复核，75 分表示主张逐项有证据，90 分还需要独立复核和可信归因。文件数量、术语数量和界面外观不加分。

## 验证与复核

使用[统一工具链](/guide/prerequisites)，输入为自己的任务及生成报告：

```bash
npm run study:check
npm run verify
```

预期核心执行、产物关联、负例、文档和框架检查通过。它们不能替你填写作品集；再逐项核对上面的六项交付物和四个评分维度。

评分引用具体产物和观察。独立审阅者先评分再看作者总分；分歧回到证据，不只取平均。

## 失败与回退

证据与结论冲突时先撤回该结论，保留原始失败。检查失败后只回退本轮候选；临时运行目录由运行器清理，报告和仍需取证的材料保留。E1 作品可以合格，但不得据此声称真实模型质量或生产可用性。
