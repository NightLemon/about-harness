# 综合项目：从可运行示例到自己的任务

综合项目把知识地图、执行代码、模型适配、评测、安全和迁移放到同一个任务中。先运行一份完整示范，再替换任务，避免从空表开始猜测最终产物。准备面试材料时，可先完成[五张面试迁移卡](/guide/interview-practice)，再把自己的脱敏证据组织为综合项目。

## 先运行已完成示例

按[环境准备](/guide/prerequisites)使用 Node.js 22+、Python 3.12、uv 0.11.16 和 Git。输入是六个固定编码任务、预审补丁与独立测试：

```bash
npm run study:demo
```

命令打印新报告的位置。预期 12 单元完整、候选 6 项通过、基线 6 项失败；每条记录都有输入、配置、Run、Trace（轨迹） 和 Result（结果） 的引用。已完成作品集位于 `examples/portfolio-completed/`，公开执行样例位于 `lab/results/public/study-demo/`。

## 用同一条证据链填写六项作品

| 作品 | 从示例读取 | 自己必须补充 |
| --- | --- | --- |
| 知识地图 | 执行链和组件职责 | 自己任务中的权威状态与验收者 |
| 最小 Harness | 工作区工具、独立测试、终态 | 新任务的工具边界与失败路径 |
| 适配卡 | 回放适配器、已知与未知用量 | 真实模型的身份与协议资格 |
| 评测报告 | 完整矩阵、失败与结果引用 | 抽样理由、任务规模与采用标准 |
| 安全评审 | 固定补丁、受限路径、清理 | 数据、主体和外部副作用风险 |
| 迁移记录 | 已填写的职责映射 | 目标产品实际运行证据 |

## 建立自己的副本

确认目标目录不存在，再复制 `examples/portfolio-starter/` 到自己的练习目录。模板的 `untested` 保留到实际验证完成；不要复制示例的 hash 冒充新输入。

先修改一个任务和一个主要配置变量。新增输入必须建立新身份，先复现基线失败，再运行候选、相邻正例和安全负例。用新输出目录生成结果，按[评分规则](/guide/portfolio)复核。

## 失败、清理与回退

若验收器只读取模型的成功声明、矩阵缺失、输入无法定位，或候选需要范围外动作，停止扩大任务。保留失败记录，恢复自己的上一版配置，再重跑最小案例。

示例临时仓库自动清理；报告不会自动删除。放弃练习时只处理自己创建的明确目录，不覆盖共享模板或其他工作树修改。

## 适用边界

已完成示例证明 E1 执行链。模型卡中的真实供应方、生产权限和跨产品迁移仍为未验证；作品集可以明确展示这些未知，而无需把所有状态改为通过。
