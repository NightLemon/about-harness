# 推理预算与模型路由优化

## 路由输入

任务类型/规模、风险、所需工具、多模态、上下文、延迟 SLO、费用上限和过去失败类型。不要按“这个模型总体更聪明”路由。

## 三档示例

- Fast path：局部、确定性、强验证；
- Standard：常规多文件/多步骤；
- Escalation：跨系统、高歧义或 baseline 多次失败。

档位只是项目建议，必须映射到目标 provider 的实际模型与预算设置。

## 晋级规则

预注册主指标的实际改善阈值，成功区间不支持明显退化，安全无回退，成本和 P90 延迟在预算内。只在失败后升级会造成 selection bias；正式比较对相同任务运行所有候选。

## 回退

协议不兼容、tool error、预算耗尽、timeout、模型不可用与安全拒绝分别路由；不要用无限重试或自动扩大权限恢复。

## 配对实验

从 20 个锁定任务中按复杂度分层，但每个候选仍运行相同任务。配置 A 使用标准预算；配置 B 只提高 reasoning 档位；配置 C 保持预算但在两次不同失败后才升级模型。保存路由决定发生前可观察的特征，不能使用任务完成后的信息训练规则。

## 失败诊断

高档位质量不变但延迟增加，说明任务可能由确定性验证主导；只有失败任务被送到强模型，会产生不可直接比较的 selection bias；fallback 循环检查 stop reason 分类与总预算。模型不可用时降级必须保留安全和协议门禁，不能自动关闭 schema 或扩大权限。
