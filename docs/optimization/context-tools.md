# 上下文与工具调优

模型适配最常见的高杠杆工作，是把它看到的信息和可选动作改得更适合它，而不是反复添加人格描述。

## 上下文调优顺序

1. **确认加载**：让 agent 列出实际加载的指令、当前目录和可用工具。
2. **删除噪声**：移除常识、过期文件清单和重复规则。
3. **增加路由**：告诉它去哪里找答案，而不是把答案全文预载。
4. **保护关键状态**：在压缩前保存目标、禁区、改动和验证。
5. **限制大输出**：过滤测试日志，分页检索结果，排除生成目录。
6. **按需能力**：低频领域知识放 skill，实时数据走工具。

## 针对模型行为调节

| 观察 | 调整 | 验证 |
| --- | --- | --- |
| 忽略末尾约束 | 缩短常驻上下文，把验收紧邻目标 | 约束遵循率 |
| 读取太多文件 | 提供入口和搜索顺序，限制 glob | 读取 token/文件数 |
| 压缩后忘记禁区 | 写任务状态；自定义压缩保留项 | 压缩后负面测试 |
| 过度依赖记忆 | 要求易变事实从权威源刷新 | 陈旧事实率 |
| 被网页指令带偏 | 标注不可信数据，副作用动作再授权 | 注入攻击集通过率 |

不要假设所有模型都以同样方式受益。较小模型通常更需要窄工具集、短指令和结构化返回；更强模型能处理开放任务，但同样会被无关上下文拖累。

## 工具调优顺序

### 1. 记录真实轨迹

收集模型选错工具、参数校验失败、重复调用和错误恢复的实例。没有轨迹就只能猜测工具说明哪里有问题。

### 2. 消除重叠

若 `search`、`find`、`lookup` 都能查代码，合并或明确各自数据域。把只读和写入拆成不同工具；把高风险动作命名得足够具体。

### 3. 收紧 schema

用枚举代替任意字符串，用对象代替嵌套命令文本，声明必填字段和长度/范围。默认值应安全，例如 `dry_run: true`。

### 4. 改善结果

成功返回最小必要数据和可继续的 ID；失败返回原因、是否可重试和副作用状态；大结果返回摘要与分页句柄。

### 5. 分配权限

按任务暴露工具，而不是为每个 session 挂载全部 MCP。只读 reviewer、实现 agent 和发布 agent 应有不同能力。

## 推理强度不是万能补偿

提高推理预算适合多约束规划、证据综合和难调试。它不能让不可见文件变可见、让坏 schema 可用、或让被 sandbox 阻止的命令成功。若工具调用在第一步就失败，先修环境；若证据齐全但方案判断反复错误，再测试更高推理强度。

## 缓存意识

支持 prompt caching 的 provider 通常更容易缓存稳定前缀。把稳定系统规则放前面，把任务和工具结果放后面；避免每轮无意义地重排大段静态文本。缓存命中只降低成本/延迟，不证明上下文质量更高。

## 完成一次调优

调优完成的证据不是“一次成功”，而是固定任务集上成功率上升，且无效调用、token、延迟或风险没有越过门槛。把最终设置写入[模型适配卡](/practice/model-playbook)并记录适用版本。
