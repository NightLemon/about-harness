# 审阅方法

本项目采用“写作—审阅—修正—验证”的连续循环。每一轮必须产生可追踪的发现，而不是只更改轮次数字。

## 一轮怎样算完成

1. 声明本轮关注面和判定标准。
2. 对当前仓库执行阅读、搜索、自动检查或构建。
3. 记录具体发现，包含页面/问题/风险。
4. 修改正文、站点或检查工具。
5. 运行与风险相称的验证。
6. 在 `docs/reviews/round-NN.md` 记录发现、修复和未决项。

## 十轮基线

| 轮次 | 主审面 | 核心问题 |
| --- | --- | --- |
| 1 | 术语与范围 | harness、agent、模型边界是否一致？ |
| 2 | 信息架构 | 新读者能否按目标找到路径？ |
| 3 | 事实与来源 | 易变产品事实是否有官方来源和日期？ |
| 4 | 模型优化方法 | 是否能从模型假设走到可复现实验？ |
| 5 | 跨 Harness 对照 | 职责映射是否准确，是否误称等价？ |
| 6 | 安全 | 权限、注入、供应链、回滚是否可操作？ |
| 7 | 评测 | 指标、重复、隔离、失败分类是否完整？ |
| 8 | 可读性 | 术语、例子、段落与学习检查是否易懂？ |
| 9 | 静态质量 | 链接、标题、代码围栏、必需页面是否通过？ |
| 10 | 构建与一致性 | GitHub Pages 构建、导航和最终主张是否一致？ |

后续轮次不必重复这个顺序。新版本可以按事实刷新、安全审计、读者反馈或新 harness 专题继续编号。

## 严重性

- **P0**：会导致危险操作、敏感数据泄露或完全错误的核心结论。
- **P1**：产品事实错误、步骤不可执行、关键学习链断裂。
- **P2**：重要歧义、遗漏、验证不足或导航问题。
- **P3**：表达、样式和低风险一致性问题。

未决项不能通过隐藏来“完成”一轮，应写入下一轮或 backlog。
