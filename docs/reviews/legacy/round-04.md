# 第 4 轮：指定模型优化方法

日期：2026-08-20

## 审阅目标

验证读者拿到一个指定模型后，能从身份和协议兼容开始，逐步得到可复现的 harness 配置，而不是直接照抄“强/快模型”路由。

## 检查方式

- 搜索模型优化、实验和适配卡中的身份、兼容、探针、基线、单变量与路由步骤。
- 从一个未知 provider 的 tool-capable 模型开始，模拟填写适配卡。
- 检查模型能力失败与 adapter/harness 失败是否可区分。

## 发现与修正

| 严重性 | 发现 | 修正 |
| --- | --- | --- |
| P1 | 原流程从能力假设开始，未要求确认模型解析结果和工具协议；adapter 失败可能被误诊为模型弱 | 新增“身份与协议”第 0 步，覆盖工具 ID、错误、多轮、截断、超时和流式行为 |
| P2 | 从能力维度直接跳到 10–30 个真实任务，首次适配成本高且难以快速发现环境断裂 | 增加 6 个小探针及其观察信号 |
| P2 | 只有候选配置，没有区分开箱默认与合理工程配置 | 增加默认基线、工程基线，实验页要求同时保存 |
| P2 | 模型适配卡无法记录协议和探针结果 | 扩充模板，加入协议、六类探针和基线字段 |
| P3 | 可能依赖模型自报版本 | 明确模型自报不是唯一证据，应读 harness/provider 元数据 |

## 验证

- 完整顺序从“确认身份”到“写入适配卡”无跳步。
- 每类探针都对应可观察信号，不以主观好坏评分。
- 运行 `npm run docs:check`。

## 未决项

尚未提供自动运行探针的跨 harness fixture；因三者的权限、事件格式和 session 隔离不同，后续应先定义中立任务格式，再写各自 adapter。
