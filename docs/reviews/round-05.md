# 第 5 轮：跨 Harness 对照

日期：2026-08-20

## 审阅目标

检查 Codex、Pi、Claude Code 的职责映射是否误称文件/功能等价，并让迁移者能识别需要直接复制、适配、重写或放弃的对象。

## 检查方式

- 审阅横向表的每一行，区分上下文、会话和文件状态。
- 搜索三份产品页中的指令文件、settings、skills、hooks、extensions 与 subagents。
- 用 `CLAUDE.md + hook + subagent` 迁移到 Pi/Codex 的例子检查语义缺口。

## 发现与修正

| 严重性 | 发现 | 修正 |
| --- | --- | --- |
| P1 | 原表把 worktree 写在“上下文恢复”中；worktree 隔离文件树，不恢复会话上下文 | 拆成“会话生命周期”和“工作区隔离”两行 |
| P2 | 相同 `SKILL.md`/MCP 名称可能让读者直接复制配置，忽略元数据、认证和工具名差异 | 增加九类对象的可迁移程度与适配要求 |
| P2 | 权限、项目信任、计划、委派和恢复被压缩成能力有/无 | 新增三组语义差异，明确不能互相替代 |
| P2 | 迁移原则缺少可执行记录格式 | 增加职责优先的迁移工作表和回归任务列 |

## 验证

- comparison 不再把 session、context、checkpoint、worktree 混为一类。
- 迁移工作表要求记录权限/副作用与回归任务。
- 运行 `npm run docs:check`。

## 未决项

未来应为同一个最小项目提供三套真实配置 fixture；当前只给语义映射，尚未用三种 CLI 自动验证加载顺序。
