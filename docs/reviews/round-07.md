# 第 7 轮：评测与复现

日期：2026-08-20

## 审阅目标

检查实验是否能复现、正确区分成功指标和失败来源，并让读者可以用项目内 artifact 真实汇总 run。

## 检查方式

- 搜索重复、随机、P50/P90、置信、judge、轨迹、holdout 与基础设施失败。
- 尝试从现有页面建立任务文件与 run 记录；检查是否有机器可读格式。
- 用 6 条示例 run 验证汇总字段和小样本区间。

## 发现与修正

| 严重性 | 发现 | 修正 |
| --- | --- | --- |
| P1 | “通过率”没有区分单次、重试后与 best-of-k，可能严重夸大默认体验 | 明确四种成功口径，要求报告所用口径 |
| P1 | 只有 Markdown/CSV 片段，没有项目内可运行 artifact | 增加任务/run JSONL、Node 汇总器与 npm 命令 |
| P2 | 随机顺序已覆盖，但没有配对分析和基础设施失败的预注册处理 | 加入同任务 A/B 配对、重跑规则和保留原失败要求 |
| P2 | 小样本只写“不代表 100%”，没有区间做法 | 增加 Wilson 95% 区间，汇总器实际计算 |
| P2 | 模型 judge 只提匿名化，没有位置偏差控制 | 增加候选顺序轮换、人工校准与确定性检查优先 |
| P2 | 轨迹隐私未和评测保存流程连接 | 在实验室链接数据流/隐私章节 |

## 验证

- `npm run eval:summary` 能读取 `evals/runs.example.jsonl` 并输出两个配置摘要。
- 示例明确声明不能用于模型结论。
- 运行 `npm run docs:check`。

汇总器故意保持最小，只处理已验证 JSONL；生产评测仍需正式 JSON Schema、价格版本、artifact hash、缺失值策略和统计检验方案。
