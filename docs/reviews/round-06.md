# 第 6 轮：安全与权限

日期：2026-08-20

## 审阅目标

检查安全章节是否覆盖模型、工具、数据、供应链、执行环境和事件响应，并处理站点自身依赖审计发现。

## 检查方式

- 搜索 secret、数据、MCP、注入、供应链、sandbox、审批、日志与回滚。
- 运行 `npm audit --json`、`npm ls vitepress vite esbuild`，核对稳定版依赖范围。
- 从 prompt injection 导致外传和第三方 extension 被替换两个场景走完预防与响应。

## 发现与修正

| 严重性 | 发现 | 修正 |
| --- | --- | --- |
| P1 | `vitepress@1.6.4` 的 Vite/esbuild 传递依赖有已知 dev-server 漏洞，当前稳定范围无自动修复 | 新增依赖安全页，说明受影响表面、静态部署边界、loopback/停服/升级缓解与复查模板 |
| P1 | 安全页强调动作权限，但没有完整的数据接收方、保留和 session 导出风险 | 增加数据流/隐私清单、短期身份、脱敏和授权回收 |
| P1 | MCP 只写“非自动可信”，缺少工具描述投毒和 server 变更控制 | 增加 schema/tool list diff、版本审查、资源级授权和失败策略 |
| P2 | Sandbox 可能被读者当作绝对边界 | 明确其例外与宿主挂载/网络/供应链风险 |
| P2 | 没有越权/泄密后的操作顺序 | 增加停止、撤销、取证、恢复、回归和组织升级六步响应 |

## 验证

- 站点运行时/开发时攻击面被明确区分，不宣称漏洞“不影响”。
- 安全检查覆盖预防、检测、响应和恢复。
- 运行 `npm run docs:check`；完整 `npm audit` 仍按记录返回非零，作为已知未决风险保留。

## 未决项

等待 VitePress 稳定依赖链提供修复；不能把“暂无 fix”当作风险关闭。GitHub Actions 当前使用 major tag，组织若要求不可变供应链，应在确定仓库策略后固定经审核的 commit SHA 并用更新工具维护。
