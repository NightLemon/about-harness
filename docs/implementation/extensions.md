# 扩展点：工具、Skill、Hook、Plugin 与 MCP

扩展首先改变信任边界，其次才增加能力。接入前记录来源、版本、权限、输入输出、失败语义、卸载和恢复方式。

## 选择最小层

- 只需确定性动作：工具或 CLI；
- 需要按需知识/流程：skill；
- 生命周期强制规则：hook；
- 需要代码、UI 或分发：plugin/extension；
- 需要跨进程能力协议：MCP server。

名字在不同产品中不完全等价。迁移时映射“谁发现、谁执行、谁授权、谁记录、谁停止”，不要逐字复制配置。

## 安全门禁

默认 deny；schema 收窄；输出限长；路径与网络 allowlist；副作用使用幂等键；失败返回可恢复错误；新依赖做许可和供应链检查。外部内容始终是不可信数据，不因来自工具而升级为指令。

## 卸载测试

禁用扩展后，核心 loop、checkpoint 和结果读取仍应工作。若卸载会破坏历史 trace，保留版本化 adapter 或迁移器。

## 工作例：选择工具还是扩展

需求只是“运行本地 schema 校验”。先暴露一个参数固定、输出限长的 CLI tool；不要为了复用一段命令安装能修改 agent loop 的 extension。只有当多个项目都需要发现、配置和生命周期事件时，才评估更高层扩展。MCP 解决跨进程协议，不自动解决 server 权限或来源可信度。

## 失败诊断

扩展输出淹没上下文，先限制字段与长度；停用后旧 trace 无法读取，补版本化 adapter；工具重复写入，增加幂等键；更新后权限扩大，回到锁定版本并审计 diff。任何自动发现机制都要测试“不安装、不信任、不联网”路径。
